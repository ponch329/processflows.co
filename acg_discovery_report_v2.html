01 — Summary

Four Structural Problems

These aren't isolated complaints. They surfaced in every conversation, in every function, at every seniority level.

Information overload at the open
Every analyst — from Ryan at the trading desk to Gordon in Denver — starts the morning processing the same high-volume email flood before the 8:40 call. Dan's framing was exact: "90% of it is like a press release that doesn't matter." The analysts are currently doing the job the AI should be doing. The 8:40 call is the daily synthesis point, and right now it depends entirely on 10 humans manually filtering overnight noise.
Manual monitoring where alerts should exist
Ryan watches 50+ pairs against a hardcoded Excel spreadsheet Sameer built years ago. There is no system that alerts him when a pair drifts. Sameer monitors broker chats all day — "dozens of broker chats, mostly regurgitation, but 10–25% of the time something sparks a trading decision" — with no summarization layer. Henry manually opens individual regulatory filings one by one after market close.
Institutional memory is not queryable
Gordon takes notes in individual Word documents per situation. Brian starts in OneNote and falls back to Word. Ethan has a discipline around OneNote but it's not searchable at scale. Gordon's exact ask: "Where's Exxon production vs. consensus for Q4 '26?" — currently unanswerable without manually digging. Henry is independently building a RAG transcript database because the problem is so obvious — but he's doing it alone, from scratch, with no front-end.
The data exists — the pipeline doesn't
Henry has 20–30+ automated pipelines running daily. Brian's production data is 2–3 days ahead of Enverus. Sameer downloads the Eclipse PNL report ~50 times a day. Jamie call summaries are being generated consistently. SS&C Eclipse, Daloopa, Lightkeeper, Enverus — all of it is live. None of it talks to anything. The raw material for a powerful system is already in place; what's missing is the connective layer.

04 — Platform

StackAI: Why and How

The platform choice is already made. Here's the specific deployment architecture and why it answers John's objections directly.

1
ACG provisions a cloud organization and IAM role
Henry sets up an AWS organization inside ACG's existing infrastructure. An IAM role is created that trusts only StackAI's account ID — cross-account access is tightly controlled. ACG can revoke this role at any time with instant termination.
Owner: Henry (ACG)
2
StackAI deploys inside ACG's VPC via IaC and helm charts
StackAI provides the infrastructure-as-code (IaC) and helm charts. All models, inference, and data processing run inside ACG's VPC. No data traverses the public internet. No credentials are stored on StackAI's side — IAM role only.
Owner: StackAI (Karissa)
3
All StackAI actions logged in ACG's own CloudTrail
Every action StackAI takes is logged in ACG's CloudTrail — not StackAI's. ACG has full audit visibility. The IAM role is scoped to deploy, update, and monitor only — StackAI has no data read access at any point.
Owner: Henry (ACG) / Atticus
4
Agent builds begin in parallel — day one
Web-fed and MCP-connected agents (Trading Alerts, Morning Brief) start building immediately — no VPC dependency. KB-dependent agents are built during weeks 1–4 and activate when the knowledge base is ready. Nothing waits on nothing.
Owner: Stephen (ProcessFlows)
On Claude for Excel: StackAI handles agents, workflows, and the knowledge base. Claude Team subscriptions cover the Excel integration — model work done directly in spreadsheets. Ethan is already using this. Two tools, complementary roles, no overlap. Both run inside controlled environments.

Pair Drift Alert
Ryan's #1 ask. A Bloomberg-data-in, alert-out pipeline that fires when any spread crosses a configurable threshold — replacing the current manual Excel monitoring entirely.
P1 — Build First Ryan
Data Sources & Inputs
  • Bloomberg price feed — intraday spread data for Ryan's pairs list
  • Ryan-provided pairs list — minimum viable: pair names + opening spread benchmark
  • Configurable threshold per pair (default: 50 bips from opening spread)
Note: Position sizing is not required for v1. Knowing the pairs is sufficient to build. Real-time vs. delayed feed to be confirmed with Henry.
Trigger & Output
  • Trigger: Event-based — fires when any pair crosses configured threshold
  • Output: Email alert to Ryan with: pair name, current spread, opening spread, magnitude of drift, timeframe
  • Delivery: Email (immediate on trigger)
  • Configurability: Ryan sets thresholds per pair; no rebuild required to adjust
Dependencies

ACGSameer sign-off on sharing pairs data with StackAI platform
StephenConfirm Bloomberg data feed path with Henry (direct API vs. export)
StackAIPrice data connector configured (Polygon or Finnhub as fallback)
Acceptance Criteria
Alert fires within 5 minutes of a pair crossing the configured threshold
Alert email contains pair name, spread magnitude, and timeframe — readable in under 10 seconds
Ryan can adjust thresholds without requiring a code change or Stephen's involvement
Zero false positives in first 48 hours of live operation (calibration session held)
Stock Signal Alert
Hourly divergence detection across 100 stocks in correlated groups. When any name diverges meaningfully from its group, Sameer and Sean get an alert — name, group, magnitude, timeframe. All thresholds configurable without a rebuild.
P0 — Highest Priority Sameer · Sean
Data Sources & Inputs
  • Hourly price data pull across 100 tickers — Polygon.io or Finnhub API (to confirm with Henry)
  • Sameer/Sean-provided grouped company list — 100 stocks organized into correlated sets
  • Configurable divergence thresholds per timeframe: intraday, daily, weekly, monthly
Explicitly not in v1: Fundamental signal layering, news integration, trade recommendations, factor models, tick-by-tick monitoring, routing to analysts.
Trigger & Output
  • Trigger: Scheduled — runs every hour during market hours
  • Logic: Calculates average return of each group, compares each stock to group average, flags divergence above threshold
  • Output: Email to Sameer and Sean — diverging stock name, its group, magnitude of divergence, timeframe
  • Quiet hours: Configurable — no alerts outside market hours unless set otherwise
Dependencies

StackAIScheduled trigger configured in StackAI workflow

Runs every hour during market hours without manual intervention
Alert correctly identifies the diverging stock, its group, and the magnitude
Sameer and Sean can adjust thresholds without a rebuild
Calibration session held within 5 business days of go-live to tune thresholds

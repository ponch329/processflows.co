01 — Summary

Four Recurring Themes

Four themes that came up across every conversation, in every function.

Manual monitoring where alerts should exist
Ryan watches 50+ pairs from a hardcoded Excel spreadsheet . No alert fires when a pair drifts. Sameer monitors dozens of broker chats all day with no summarization layer. Henry manually opens regulatory filings one by one after market close to determine relevance.
Institutional memory is not queryable

04 — Platform

StackAI: Why and How

The contract is signed. Here's the deployment architecture and why it addresses the security requirements John raised.

1
ACG provisions a cloud organization and IAM role
ACG sets up an AWS organization inside existing infrastructure. An IAM role is created that trusts only StackAI's account ID — cross-account access is tightly controlled. ACG can revoke this role at any time with instant termination.
2
StackAI deploys inside ACG's VPC via IaC and helm charts
StackAI provides the infrastructure-as-code (IaC) and helm charts. All models, inference, and data processing run inside ACG's VPC. No data traverses the public internet. No credentials are stored on StackAI's side. IAM role only.
3
All StackAI actions logged in ACG's own CloudTrail
Every action StackAI takes is logged in ACG's CloudTrail, not StackAI's. ACG has full audit visibility. The IAM role is scoped to deploy, update, and monitor only. StackAI has no data read access at any point.
4
Agent builds begin in parallel, starting day one
Web-fed and MCP-connected agents (Trading Alerts, Morning Brief) start building immediately, no VPC dependency. KB-dependent agents are built during weeks 1–4 and activate when the knowledge base is ready.
On Claude for Excel: StackAI handles agents, workflows, and the knowledge base. Claude Team subscriptions cover the Excel integration. Model work done directly in spreadsheets. Ethan is already using this. Two tools, complementary roles, no overlap. Both run inside controlled environments.

08b — Bloomberg Integration

Bloomberg: Integration Paths

Bloomberg is central to ACG's data infrastructure. Three integration paths exist — each with different requirements, cost, and timeline. The right path depends on ACG's current subscription level.

1
Community blpapi-mcp (Terminal-based)
An open-source MCP server that wraps Bloomberg's blpapi and exposes real-time Terminal data to AI agents. The server runs locally on a machine with a licensed Terminal session active. No separate API key needed, the Terminal session provides authentication. Supports equity, fixed income, credit, screening, earnings calendar, and macro events.
Requirements: Bloomberg Terminal running and logged in (localhost:8194). Bloomberg C++ SDK and Python SDK installed. Terminal license only — no Data License required.

Legal note: The open-source project (github.com/djsamseng/blpapi-mcp) explicitly states it is not affiliated with Bloomberg Finance L.P. and that Bloomberg data use requires a valid Terminal subscription. The code itself is open source; the data access is governed by ACG's existing Terminal license agreement. Best for: Fastest path to Bloomberg data integration. Good for price feeds, pair monitoring, and intraday data. Henry is the right person to deploy and run this.
2
Bloomberg Server API (SAPI)
Bloomberg's official server-side API, the same real-time market data, historical data, and calculation tools available on the Terminal, accessible programmatically. SAPI integrates Bloomberg data with third-party applications including proprietary builds. Leverages existing Terminal exchange entitlements, so no separate data licensing agreement is required. Available in Python, C++, Java, and .NET.
Requirements: Existing Terminal license. Bloomberg SAPI add-on (separate from the base Terminal subscription — Bloomberg offers four service tiers). SAPI Plus/Premium options let Bloomberg manage the infrastructure entirely.

Questions for ACG: Does the current Bloomberg contract include SAPI access, or is it Terminal-only? If Terminal-only, what tier of SAPI would cover the use cases needed (price feeds, historical data, chat API)? Follow-up

Best for: Production-grade integration. This is the right path for the Stock Signal Alert, Pair Drift, and eventually the Bloomberg Chat API summary.
3
Bloomberg Data License (B-PIPE)
Bloomberg's enterprise data feed — 50M+ securities, 56,000 fields, REST API or SFTP, available natively in major cloud providers. Separate from the Terminal subscription. Designed for feeding accounting, portfolio management, and compliance systems at scale.
Requirements: Separate Bloomberg Data License contract. Significant additional cost — typically $50K–$150K+/year depending on scope and data fields.

Best for: Large-scale data ingestion at enterprise level. Likely overkill for ACG's Phase 1–2 needs. Worth flagging as a long-term path if the SAPI tiers don't cover everything needed.
4
Manual Export Workflow
Analysts export Bloomberg data (CSV/Excel) on a schedule. StackAI ingests the exports into the knowledge base or feeds them directly into agents. Zero licensing risk. No new contract required. Deployable immediately.
Best for: Historical data ingestion, reference data, and any dataset that doesn't require real-time refresh. A practical fallback for anything not covered by blpapi-mcp or SAPI in Phase 1.
